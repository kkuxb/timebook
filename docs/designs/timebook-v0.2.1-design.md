## 1. 业务合同

- **使用者与触发**：个人单用户在 `Windows` 轻量桌面端、桌面/手机浏览器及 `PWA` 中滚动长页面浏览记录、管理当日/全部待办，以及在「标签」页对不再使用的二级事项标签执行停用或重新启用。
- **输入与来源**：
  1. 在任意较长的页面（如「历史」「今日」「日历」「标签」）向下滚动并点击顶部导航切换模块或操作设置/窗口按钮；
  2. 在「今日」页待办区（「今日」及「全部未完成」视图）新建或编辑待办的截止日期 `due_date`；
  3. 在「标签」页对二级事项点击「停用」，或打开「已停用」弹窗查看并点击「重新启用」。
- **输出与去向**：
  1. **顶部导航常驻顶部**：桌面定制标题栏与网页端顶栏始终吸顶固定在视口最上方，向下滚动页面时随时可切页与操控右上角按钮；
  2. **待办双视图按截止时间排序**：「今日」与「全部未完成」待办列表统一按「未完成在前、已完成沉底；组内截止日期由近到远；未设截止日期排最后；同截止日期或均无截止日期按最新创建在前」即时重排；
  3. **二级事项无损停用与重新启用**：停用后仅从「标签」页主列表及各新建/选标签入口隐藏，且不再参与所属模块卡片顶部汇总及占比分母计算；历史专注记录与全站统计 100% 保留原标签名与颜色；可在「已停用」列表中随时查看与一键恢复启用，停用状态完整持久化并支持单机/`NAS` 多端同步。
- **完成判据**：
  - 全仓 `@timebook/core`、`@timebook/api`、`Vitest` 单测与 `Rust` 原生单测 100% 通过，`TypeScript` 类型检查、全栈构建（含 `PWA`）与 `Windows` 桌面端编译打包通过；
  - 四项独立隔离验收场景（`P1`–`P4`）全部满足合格判据，且关键视觉截图核验符合 [视觉与动效设计规范](../设计规范.md)。
- **质量底线（不可妥协）**：
  1. **旧版 `v0.2.0` 数据 100% 零损无感升级**：存量 `SQLite` 数据库（`tags` 表无 `disabled_at` 列）与桌面端本地快照 `timebook-local.json`（标签对象无 `disabled_at` 键）在新版启动后自动兼容，所有存量标签默认全部处于启用状态，绝不能因字段缺失误判为已停用；
  2. **停用不影响任何既有记录与统计**：已停用事项名下的所有历史/进行中专注记录、待办及日/周/月/年统计数据必须原样保留原标签名与所属模块颜色，严禁变成「未分类」；
  3. **多端同步一致**：停用与重新启用操作在单机本地落盘、单机转连合并以及与服务端双向增量同步时保持严格一致。
- **本版非目标（明确不做）**：
  - 不在顶部导航栏新增「新建待办」快捷按钮（`C-18`）；
  - 不对一级模块增加停用功能（仅支持二级事项标签停用与重新启用）；
  - 不改变统计页与日历页原有的周期汇总算法。

## 2. 关键设计与交互细则

### 2.1 顶部导航栏常驻吸顶（已确认 `C-18`）

1. **粘性吸顶方案（保持原生主滚动）**：
   - 采用视口级 `position: sticky; top: 0; z-index: 25` 实现常驻顶部，**不将主区域改为内部独立 `overflow: auto` 容器**，以保持窗口/页面原生滚动体验并确保「日历」页拖拽坐标与「历史」页悬浮批量栏定位 100% 稳定；
   - 保持现有顶栏结构与全部按钮不变，不新增任何待办入口。
2. **桌面端定制标题栏（`DesktopTitlebar.tsx`）**：
   - 根 `<header className="tb-desktop-titlebar">` 增加 `position: 'sticky', top: 0, zIndex: 25`（保留原有 `height: 56`、`background: '#FFFFFF'`、`borderBottom: '1px solid #E8EAF1'` 及 `data-tauri-drag-region` 拖拽区）；
   - 当主窗口垂直向下滚动时，标题栏牢牢吸附在窗口最顶部，随时可拖拽窗口、切换五栏导航、查看同步胶囊及点击设置/小窗/最小化/关闭按钮。
3. **网页端及手机端顶栏（`AppShell.tsx` + `tokens.css`）**：
   - 用全宽吸顶外层容器 `.tb-header-wrap` 包裹原本居中的 `<header className="tb-header">`：
     - `.tb-header-wrap`：`position: sticky; top: 0; z-index: 25; width: 100%; background: rgba(246, 247, 250, 0.92); backdrop-filter: blur(10px); border-bottom: 1px solid rgba(232, 234, 241, 0.88);`
     - 内层 `.tb-header` 保持 `max-width: 1360px; margin: 0 auto;`，微调桌面端内边距为 `14px 40px`（手机端 `10px 16px`），同时将 `.tb-main` 上内边距微调为 `20px`（手机端 `14px`），确保首屏视觉留白协调，且滚页时正文文字不会从顶栏两侧或底部透明缝隙穿帮透出；
   - 手机窄屏下继续保留顶部品牌/同步状态/设置栏吸顶 + 底部五栏导航固定，互不冲突。
4. **全站层级秩序（`z-index`）**：
   - 正文卡片与日历色块：`1`–`4`；
   - 历史页行内弹出浮层（`data-history-popover`）：`30`（确保不被顶栏或相邻行遮挡）；
   - 顶部导航栏（`.tb-header-wrap` 与 `.tb-desktop-titlebar`）：`25`；
   - 手机端底部迷你条与手机底栏：`29`–`30`；
   - 历史页底部批量操作栏：`35`；
   - 居中模态弹窗遮罩（`.modal-backdrop`）：`40`；
   - 右侧设置抽屉遮罩（`.drawer-backdrop`）：`50`。
   - 上述层级确保打开任意弹窗或抽屉时，半透明深色遮罩完整覆盖顶部导航栏。

### 2.2 待办列表按截止时间排序（已确认 `C-19`）

1. **统一排序比较器 `compareTodoViewItems(a, b)`（置于 `@timebook/core` `todos.ts`）**：
   - 对 `TodoViewItem` 统一按以下 4 级优先级排序：
     1. **完成状态优先**：`a.done !== b.done` 时，未完成（`false`）排在已完成（`true`）之前；
     2. **有无截止日期优先**：有 `due_date` 的排在未设置截止日期（`due_date === null`）之前；
     3. **截止日期由近到远**：双方均有 `due_date` 时，按 `'YYYY-MM-DD'` 字典序升序（`a.todo.due_date.localeCompare(b.todo.due_date)`），已过期越久的日期最早自动排在最前，其次是今天截止，再到未来日期；
     4. **同截止日期或均无截止日期的平局打破**：按创建时间 `created_at` 倒序排列（`b.todo.created_at - a.todo.created_at`），即最新创建的待办排在前面；若 `created_at` 也相同则按 `a.todo.id.localeCompare(b.todo.id)` 保证确定性稳定顺序。
2. **双视图统一生效**：
   - **`getTodayTodos`（「今日」视图）** 与 **`getAllPendingTodos`（「全部未完成」视图）** 均直接调用 `compareTodoViewItems` 排序；
   - 重复待办（含每天/每周/每月重复）今日已打卡完成时 `done = true` 自动沉入末尾，尚未完成时按其自身 `due_date` 与 `created_at` 正常参与排序；
   - 用户在 `TodoEditorModal` 修改任意待办的截止日期（设置、修改或清除）保存后，待办区列表立即按新规则实时重排。

### 2.3 二级事项标签停用与重新启用（已确认 `C-20`）

#### 2.3.1 数据模型与向后兼容契约

1. **字段定义**：
   - `tags` 表增加可空整型列 `disabled_at`（`INTEGER`，可空：`null` 或 `undefined` 表示启用中；非空毫秒时间戳表示停用时刻）；
   - `@timebook/core` 新增辅助判定纯函数 `isTagDisabled(tag: Pick<TagEntity, 'disabled_at'> | null | undefined): boolean`，实现为 `typeof tag?.disabled_at === 'number'`（对 `null` 与 `undefined` 均安全返回 `false`）。
2. **Schema 与增量同步扩展**：
   - `packages/core/src/types.ts`：`TAG_SCHEMA` 新增 `disabled_at: z.number().int().nullable().optional()`；`MUTATION_ITEM_SCHEMA` 中 `'tag.upsert'` 的 `payload` 新增 `disabled_at: z.number().int().nullable().optional()`；
   - `apps/api/src/db/schema.ts` 与 `client.ts`：`tags` 建表包含 `disabled_at INTEGER`；老数据库启动时检查 `PRAGMA table_info(tags)`，若缺失 `disabled_at` 列则自动执行 `ALTER TABLE tags ADD COLUMN disabled_at INTEGER`；
   - `apps/api/src/sync.ts`：`tag.upsert` 更新时兼容处理 `disabled_at`——当请求显式传入 `null` 或数字时直接覆盖写入；若旧版本客户端省略该字段（`undefined`），更新已有记录时保持数据库当前 `disabled_at` 不被误清空，新建记录则写入 `NULL`；
   - `packages/core/src/merge.ts`：`planLocalToRemoteMerge` 在生成 `tag.upsert` 变更及合并标签对象时显式透传 `disabled_at: tag.disabled_at ?? null`；
   - `apps/web/src/db/dexie.ts` 与 `useAppStore.ts`：从 `IndexedDB` 或桌面本地快照 `timebook-local.json` 加载标签时，统一标准化补齐 `disabled_at: t.disabled_at ?? null`。
3. **状态变更通道**：
   - `useAppStore` 中 `upsertTag` 与 `applyOptimisticMutation('tag.upsert')` 透传 `disabled_at: tag.disabled_at ?? null`；
   - 新增动作 `setTagDisabled(id: string, disabled: boolean): Promise<void>`：读取目标标签并通过既有 `upsertTag({ ...tag, disabled_at: disabled ? nowMs() : null })` 完成乐观更新、本地存储、桌面快照/托盘刷新及多端同步入队。

#### 2.3.2 全站标签查找表拆分（`apps/web/src/lib/labels.ts`）

`buildTagLookup(modules, tags)` 输出结构调整如下：
- `activeModules`：全部未软删除（`deleted_at === null`）的一级模块；
- `allTags`：全部未软删除且所属模块未软删除的二级事项（**同时包含启用中与已停用**）；
- `enabledTags`：`allTags` 中 `!isTagDisabled(t)` 的启用中事项；
- `disabledTags`：`allTags` 中 `isTagDisabled(t)` 的已停用事项；
- `activeTags`：保持等同于 `enabledTags`（确保既有的快捷选标签消费方无感知兼容，而真正需要覆盖停用标签的读取场景显式使用 `allTags` / `tagById`）；
- `moduleById`：基于 `activeModules` 构建；
- `tagById`：**基于 `allTags` 构建**——确保 `getTagStyle` 与 `formatSessionDisplayTitle` 对已停用标签的专注记录、待办及导出结果 100% 正常解析展示原标签名与原模块配色，绝不退化成「未分类」。

#### 2.3.3 「标签」页（`TagsPage.tsx`）交互设计

1. **事项行操作与停用触发**：
   - 每个启用中事项行尾的操作按钮区（`act`，桌面悬停渐显、手机端常显）由「修改 / 删除」扩展为 **「停用 / 修改 / 删除」** 三个轻量图标按钮；
   - 点击「停用」按钮（`aria-label="停用事项 ${t.name}"`，`title="停用（不影响历史记录与统计）"`，`data-testid="disable-tag-${t.id}"`）立即将 `disabled_at` 设为当前时间戳，无需二次弹窗打断，并即刻从主列表移出。
2. **模块卡片统计与占比重算**：
   - 每个模块卡片仅展示该模块下**启用中**的二级事项（`enabledTags`）；
   - 模块卡片顶部浅色汇总区（**累计 / 事项 / 记录**）以及每条启用中事项的进度条百分比 `pct`，均**仅基于当前模块下的启用中事项统计计算**（与百分比分母严格一致，全部启用项占比之和保持 100%）。
3. **「已停用」入口按钮与管理弹窗**：
   - 「标签」页头部右侧按钮区在「`+ 新建模块`」旁新增次级按钮 **「已停用」**（`data-testid="open-disabled-tags-btn"`，当 `disabledTags.length > 0` 时展示数量徽标，如 `已停用 2`）；
   - 点击打开 **「已停用事项」弹窗**（`data-testid="disabled-tags-modal"`）：
     - 头部说明清晰告知：「这些事项已从标签页、开始专注和新建选择中隐藏；它们关联的历史记录与统计数据仍完整保留。」；
     - 若暂无已停用事项，展示温和空状态提示；
     - 有已停用事项时按所属一级模块分组列出每条已停用事项，展示事项名、模块色点、历史累计时长与记录次数，右侧提供醒目的 **「重新启用」** 按钮（`data-testid="enable-tag-${t.id}"`）与 **「删除」** 图标按钮（点击触发 `TagDeleteModal`）；
     - 点击「重新启用」立即将该标签 `disabled_at` 置回 `null`，事项即时回到对应模块主列表并恢复参与模块汇总与占比计算。
4. **重名冲突校验与提示**：
   - 在新建或修改事项弹窗中，名称去重检查从 `lookup.allTags`（同模块下未删全部事项，含已停用）校验；
   - 若与已停用事项重名，保存按钮禁用并展示精准提示：「这个模块里已有同名的已停用事项，可直接到右上角「已停用」列表中重新启用」。

## 4. 必过验收场景（`P1`–`P4`，已确认 `C-21`）
