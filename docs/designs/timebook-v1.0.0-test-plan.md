## 一、测试对象与隔离准备规程（`qa` 必读）

1. **只测独立发布包，绝不测开发源码目录**：
   - 被测物：`dev` 在面板交接元数据中提供的 `package_path`（即 `workspace-data/outputs/timebook/v1.0.0-R<轮次>/timebook.zip`）。
   - 解压与完整性校验：
     ```powershell
     python "<fde-qa技能目录>/scripts/unpack_verify.py" --zip "<package_path>" --dest "<项目根>/workspace-data/tmp/qa/v1.0.0-R<轮次>/pkg"
     ```
     若校验失败，直接 `@dev [changes_requested]` 打回，理由写“发布包校验失败”。
2. **隔离准备与业务场景计量分离（遵循 `fde-pm` 规范）**：
   - 解压后得到纯净副本目录 `<pkg_dir> = .../pkg/timebook`。
   - **包内静态必查项（父级 `qa` 先做，出现任一项直接判不合格打回）**：
     - 搜索包内所有文件，确认**不含** `.env`（仅允许 `.env.example`）、`*.sqlite*`、真实用户家庭内网 `IP`（如 `192.168.` 硬编码生产配置，示例代码除外但部署文档须用占位符）、`SSH` 用户名或测试专用后门句（如“预设回答”“测试输入”）。
   - **统一依赖与构建准备（单列准备时间，不计入单场景业务时长）**：父级 `qa` 在 `<pkg_dir>` 内统一执行一次依赖安装、单元测试回归（`vitest run`）与生产构建（`build`），确认构建产物齐全后再派发隔离子智能体跑 `A1`–`A6` 场景，避免 6 个子智能体各自重复下载安装 `node_modules`。
3. **每个验收场景完全隔离**：
   - 每个场景（`A1`–`A6`）均通过 `invoke_subagent(TypeName="self", Role="QA 场景 <编号> 隔离测试", Prompt=...)` 启动全新独立子智能体执行。
   - 每个场景使用各自独立的输出与数据目录：`workspace-data/tmp/qa/v1.0.0-R<轮次>/cases/<编号>-run1/`（传入独立的 `DATA_DIR`、独立的测试口令如 `qa-test-pass-<编号>`，并分配互不冲突的本地空闲端口如 `14101`～`14106` 启动该场景专属的 `<pkg_dir>` 生产服务端进程，场景结束前由该子智能体停止自己启动的端口进程并保留数据库与截图证据）。
   - **注意浏览器隔离**：若使用无头 `Playwright`（随开发依赖或独立浏览器实例）访问本地 `http://127.0.0.1:<port>`，可安全独立运行且**不抢占用户的日常桌面浏览器焦点**；严禁关闭或干扰用户宿主机已打开的 `Chrome` 窗口。

## 三、预算与计量口径

| 指标 | 目标值 | 硬上限 | 计量口径与说明 |
| --- | --- | --- | --- |
| **产品自身运行时模型消耗** | `0 Token` | `0 Token` | 应用运行期为纯本地与 `SQLite` 确定性逻辑，不得发起任何外部大模型请求 |
| **前端核心统计计算耗时** | `< 20 ms` | `100 ms` | 5,000 条记录规模下单次周期统计与空档计算纯函数耗时（由单测/性能断言验证） |
| **单验收场景盲测时长** | `<= 480 秒` | `900 秒` | 隔离子智能体 `transcript.jsonl` 首尾 `created_at` 真实秒数 `duration_seconds` |
| **测试子智能体 `Token` 与步数** | 实测记录（首版无基线） | 暂不设硬限，如实记录 | 从子智能体 `transcript.jsonl` 提取真实 `api_calls` 与 `tokens`（无原生字段填 `null` 标为不可用，**严禁按字符估算**） |
| **研发–测试返修轮次** | `1–2 轮` | **最多 `3 轮`** | 超出 3 轮仍未收敛须 `@coordinator [blocked]` 交 `PM` 与用户裁定 |

## 四、副作用与安全授权边界

- **允许的操作**：
  - 在 `<项目根>/workspace-data/tmp/qa/v1.0.0-R<轮次>/` 下解压被测包、创建临时 `SQLite` 数据库与备份文件、保存截图与计量文件；
  - 在本机回环地址 `127.0.0.1` 的空闲高端口（`14100+`）临时启动与关闭被测 `Node` 服务进程，并用无头 `Playwright` 访问该本地端口；
  - 向 `<项目根>/docs/deliveries/timebook-v1.0.0-R<轮次>-test-report.md` 写入七维测试报告。
- **严禁的操作**：
  - 严禁修改 `<pkg_dir>` 被测包内容或项目源码目录代码；
  - **严禁调用任何 `Notion` 写入/修改/删除工具**，严禁连接或操作用户真实的绿联 `NAS`（`SSH` 部署留待用户验收本地包通过后按需执行）；
  - 严禁关闭、抢占或修改用户宿主机日常正在使用的浏览器窗口及全局系统代理设置；
  - 严禁读写 `H:/个人项目/timebook` 以外的其他项目目录（如 `h:/谷米`）。
- **停止条件**：若发现包内含真实凭据、核心数据丢失或达到 3 轮返修上限，立即停止并按 `fde-qa` 路由规则上报。

## 五、通过规则

1. 包内静态必查项全部清白、`Vitest` 单测与集成测试 100% 通过；
2. `A1`–`A6` 六个隔离子智能体盲测场景全部符合合格判据，页面关键截图经 `qa` 亲眼核对符合 [设计规范](../设计规范.md)（无错位、无乱码、无硬编码违规色）；
3. 无任何“必须修复”级缺陷，且未超出时长硬上限；
满足以上全部条件，`qa` 方可撰写七维报告并在面板发送 `@coordinator [done]` 移交 `PM` 进行独立复核与用户验收。
