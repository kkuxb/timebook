## 1. 业务合同

- **使用者与触发**：个人单用户日常在电脑浏览器与手机（`PWA` 添加到主屏幕）访问；通过访问口令一次登录（`180` 天有效签名 `Cookie`）。
- **输入与来源**：
  1. 日常操作：开始/结束/取消专注计时（支持多条并行）、点选空档或日历拖拽补记录、管理两级标签（模块/事项）、新增与管理待办（含每天/每周几/每月几号重复规则）。
  2. 历史迁移：用户在设置抽屉上传从 `Notion` 导出的 `CSV` 文件（`时间标签`、`专注记录`、可选 `待办`）。
- **输出与去向**：
  1. 四大核心视图：**今日页**、**日历页**、**统计页**、**标签页**（含桌面端与移动端自适应布局及手机底部迷你计时条）。
  2. 右上角「**数据已同步**」四态断联监控 + 旁的「**设置**」抽屉（`Notion` 导入预览对账与整批撤销、全量 `JSON`/`CSV` 导出、30 天软删除回收站恢复、退出登录）。
  3. 持久化数据：绿联 `NAS` 容器挂载目录下的 `/data/timebook.sqlite` 及每日凌晨 03:00 自动备份 `/data/backups`（保留最近 30 份日备 + 每周全量 `JSON` 导出）。
- **完成判据**：
  - 核心算法纯函数（周期划分、跨零点切分、20 分钟空档、统计聚合、重复待办、`Notion CSV` 解析）100% 通过单元测试；
  - 四个主页面、设置抽屉、断网暂存队列自动补传、`Notion` 真实结构导入对账与整批撤销、全量导出、`Docker` 容器构建与健康检查全部跑通并通过独立 `QA` 盲测（`A1`–`A6`）。
- **质量底线（不可妥协）**：
  1. **数据零丢失与幂等同步**：本机修改先入 `IndexedDB` 队列再异步提交，断网/服务重启期间操作不丢、恢复后按序补传且严格幂等；健康检查必须真实读写 `SQLite` `heartbeat` 表。
  2. **统计口径严密**：固定按 `Asia/Shanghai` 划分天/周（周一起）/月/年；跨 0 点记录按实际毫秒时长精确切分到相邻自然日；同时进行的记录各自累加；**统计页与日历页仅计算和展示已结束记录**，今日页顶部模块概览与时间线实时纳入进行中计时。
  3. **历史导入可核对、可后悔**：导入前必须展示总条数、时间跨度、各模块累计时长预览及异常项处理，支持按 `import_batch` 一键整批撤销。
  4. **视觉还原度**：色彩角色、模块四档色、字号字重、圆角阴影与悬浮动效严格对齐 [设计规范](../设计规范.md) 与 `prototype/` 原型，禁止散落硬编码色值。
- **本版非目标（明确不做）**：多用户账号体系、番茄钟/白噪音、手动归档按钮、记录备注字段、忘记结束计时提醒、复杂间隔重复规则（如每隔 N 天/法定工作日）、手机端日历长按拖拽补录（手机首版用补记录按钮）、`Tauri` 桌面壳与悬浮小窗。

## 2. 关键设计与交互细则（已冻结）

### 2.1 导航与「设置」入口（`C-02`）
- **四栏主导航不变**：桌面端顶部居中分段导航、手机端底部固定标签栏均为 `今日 | 日历 | 统计 | 标签`。
- **右上角状态与设置区**：右侧并列展示「数据已同步」四态胶囊（点击弹出上次保存时间、待保存条数、错误原因与「立即重试」详情气泡）与一个克制的**齿轮图标按钮（「设置」）**。
- **设置抽屉 / 弹窗**：包含四个功能区：
  1. **从 `Notion` 导入历史数据**：支持一次选多个 `CSV` 文件 → 解析预览（有效记录数、起止日期、各模块总时长对比）→ 问题项逐条/批量处理 → 确认导入 → 已导入批次列表与「整批撤销」。
  2. **数据导出与备份**：一键下载全量 `JSON`（含全部表）或可读明细 `CSV`（专注记录明细），展示服务端最近一次自动备份时间。
  3. **回收站（最近 30 天已删除）**：展示软删除未满 30 天的模块、事项、专注记录、待办，支持单条「恢复」（恢复子项时若父级也在软删状态则连同父级恢复或提示）。
  4. **账户与设备**：展示服务健康状态与「退出当前设备」按钮。

### 2.2 今日页与待办完整闭环（`C-01`、`C-05`）
- **顶部概览**：星期 + 日期（黄色高亮底线）+ 所有未删模块的今日用时卡片（已结束切分到今日的时长 + 进行中计时落在今日的实时时长，每分钟刷新）+ 右侧唯一主黄按钮「开始专注」。
- **待办区**：
  - 标题栏：`待办` + 完成进度徽标（如 `3 / 4`，按今日视图分母分子统计）+ **「今日 / 全部未完成」轻量分段切换** + 右侧快速添加框（输入标题回车，默认创建 `plan_date = 今天`、未选标签的一次性待办）。
  - 过滤排序：「今日」视图展示 `plan_date <= 今天` 或 `plan_date` 为空的未完成一次性待办、今日命中规则的重复待办，以及今天完成的待办（排在末尾、半透明划线）；「全部未完成」视图按计划日期升序展示所有未完成一次性待办及全部重复待办（方便查看和修改未来日期的待办）。
  - **编辑待办弹窗**（点击待办卡片标题或元信息区域打开）：支持修改标题、选择事项标签（可清空为未分类）、设置计划日期（今天/明天/清除/自定义日期）、截止日期（卡片自动计算显示「截止 今天 / 还剩 N 天 / 已过期 N 天」）、配置重复规则（不重复 / 每天 / 每周多选周几 `1..7` / 每月多选日期 `1..31`）、左下角红色文字按钮「删除待办」。
  - **已投入时长**：一次性待办统计关联该 `todo_id` 的全部未删记录时长（含进行中）；重复待办仅统计北京时间**今日这一轮**关联该 `todo_id` 的时长（含进行中）。
- **专注区与时间线**：
  - 进行中计时卡：支持多条同时运行，每秒刷新读数；点击「开始专注」立即创建 `end_at = null`、`title = null` 的计时并弹出标签选择框（可点「稍后再选」）；卡片上支持「换标签 / 选标签」、内联或弹窗修改可选标题、「结束」（`end_at = 当前校正时间`）、「取消」（硬删除或软删除不计入历史统计与回收站，按方案 3.2「删除这条进行中的记录，不留痕迹」直接物理删除或标记取消不进回收站）。
  - 手机端底部迷你计时条：窄屏（`< 768px`）下有进行中计时时，在底部标签栏上方常驻迷你计时条（显示进行中数量与最早开始的一条读数，点击展开或平滑定位至专注区）。
  - 时间线与空档：支持 `‹ ›` 切换日期（不可切未来）；合并当天所有记录区间（看今天时含进行中计时），仅将**相邻两段之间 `>= 20 分钟`** 的空白标为橙色斜纹空档（一天首条记录前、最后一条记录后至当前均不算空档）；点击空档或「补记录」打开弹窗（默认回填最近一段空档起止）。

### 2.3 记录标题、编辑弹窗与未分类规则（`C-05`）
- **可选标题（`title`）**：补记录/编辑记录弹窗增加单行可选输入框「具体内容（可选，如：谷米开发）」；当 `title` 非空且不等于事项标签名时，时间线行与日历色块显示为「事项名 · 标题」（未分类时显示「未分类 · 标题」）；无独立标题时直接显示事项名（未分类显示「未分类」）。
- **未分类保存放行**：补录与编辑弹窗允许不选事项标签（存为 `tag_id = null` 未分类，时间条/日历/统计以 `#B8BDC9` 灰色呈现）；当结束时间早于开始时间时自动标注「· 次日」按跨次日计算时长，校验时长 `> 0` 且 `<= 24 小时`；与其他记录重叠时显示温和提示文案但不阻止保存。

### 2.4 日历页与统计页口径（`C-02`、`C-05`）
- **日历页**：
  - **仅渲染已结束记录**（跨零点记录按 `00:00` 切分后在对应自然日列各自渲染片段，点击任一片段编辑原完整记录）。
  - 桌面端为周一至周日 7 天视图：主网格 `06:00–24:00`；若某天 `00:00–06:00` 存在记录片段，在该列顶部表头下方展示紧凑提示条（如 `06:00 前 · 1 条`），点击可弹出列表并点选编辑；空白处按下拖拽以 15 分钟吸附预览，松手打开补记录弹窗（单击不拖默认 1 小时，未来日期禁拖）；重叠时段自动分列并排显示；今天列显示当前时刻横线指示器。
  - 手机端（`< 768px`）：默认 3 天视图（支持切换 3 天 / 单日），通过顶部「补记录」按钮录入。
- **统计页**：
  - **仅统计已结束记录**；支持 `日 / 周 / 月 / 年` 四个周期及 `‹ ›` 翻页（不可翻至未来），支持 `模块 / 具体事项` 两个维度切换。
  - 四张核心指标卡：总时长（对比上一周期增减）、日均（历史完整周期除以周期总天数，包含今天的当前周期除以从周期首日到今天已过去的天数）、花得最多、**专注次数**（按该周期内实际落入时长的**独立 `session.id` 去重计数**）。
  - 图表：手写 `SVG` 环形图 + 占比排行条（同模块多事项按模块主色与白色混合 `0% / 22% / 44% / 66%` 循环区分，未分类使用 `#B8BDC9`）+ 按模块分色堆叠柱状趋势图（日看 24 小时、周/月看每天、年看 12 个月）。

### 2.5 标签管理与级联规则（`C-05`）
- 空数据库首次初始化时默认预置 4 个基础模块（`工作` `blue`、`学习` `violet`、`游戏` `teal`、`锻炼` `rose`），确保开箱即用；导入 `Notion` 标签时同名模块直接合并复用。
- 模块（一级，8 套预设四档配色，两模块选同色时显示温和提醒）与事项（二级，同模块内未删除事项禁重名，跨模块移动时历史记录自动随事项归入新模块）。
- 删除事项/模块：无关联记录（且模块下无事项）时直接软删除；有关联数据时二选一：
  1. **迁移（默认推荐）**：将该事项的专注记录、待办及进行中计时全部迁至选定目标事项（删除模块时将该模块下所有事项迁至选定目标模块）；
  2. **连同记录一起删除**：软删除该事项（或该模块及其下事项）与关联的已结束专注记录（提示将减少的小时数，30 天内可在回收站恢复），**关联的待办保留但清空 `tag_id` 转为未分类，关联的进行中计时同样清空 `tag_id` 转为未分类而不中断计时**。

### 2.6 基于真实 `Notion` 结构的历史导入（`C-04`）
1. **`时间标签.csv`**：按列名 `标签`、`一级标签`、`颜色` 解析。`一级标签` 为空者作为模块（同名复用已有模块，新模块按 `工作→blue / 学习→violet / 游戏→teal / 锻炼→rose` 及未占用预设色分配）；`一级标签` 非空者剥离 ` (https://...)` 后缀匹配父模块建立事项（同名复用）。
2. **`专注记录.csv`**：按列名 `日历标题`、`状态`、`标签`、`待办`、`开始`、`结束` 解析。忽略 `状态` 为 `已取消` 或 `未开始` 的行；支持中文/斜杠/英文/`ISO` 日期时间解析（无时区标识按 `Asia/Shanghai` 解释）；标题优先取 `日历标题`（若为空回退取 `待办` 剥离链接后的名称；若与匹配到的二级事项名完全一致则存 `null`）；将无结束时间、结束不晚于开始、单条超 24 小时、标签为空、标签只命中一级模块或未命中的行归入「问题项确认列表」，支持逐条或批量修正/跳过/设为未分类后生成唯一 `import_batch` 入库。
3. **`待办.csv`（可选）**：按列名 `事项`、`状态`、`执行日期`、`截止日期`（可选 `标签`）解析，仅导入 `状态 != Done` 的未完成待办。

## 3. 技术架构與绿联 `NAS` 部署设计（`C-06`）

### 3.1 仓库与组件架构
- `packages/core`：共享常量、`Zod` 数据契约、周期/跨天切分/空档/统计/重复待办纯函数及 `Vitest` 单测。
- `tools/notion-import`：`CSV` 解析、`Notion` 三表映射、预览统计与异常检测纯函数及 `Vitest` 单测。
- `apps/api`：`Node 20+` + `Hono` + `Drizzle ORM` + `better-sqlite3`（`WAL` 模式）。实现登录鉴权与限流、真读写健康检查、增量同步与 `applied_mutations` 幂等提交、导入与批次撤销、导出、回收站恢复、每日 03:00 在线备份（保留 30 份日备 + 每周 `JSON`）及前端静态产物托管。
- `apps/web`：`React 18` + `Vite` + `Zustand` + `Dexie` + `date-fns` / `date-fns-tz` + `vite-plugin-pwa`。内置本地离线队列与时钟偏移校正。

### 3.2 绿联 `DXP4800 Plus`（`UGOS Pro`）部署与外网 `HTTPS` 方案
根据对用户绿联 `NAS` 的只读探针核查，采用对新手最友好、免买域名、免改路由器端口转发的组合方案（详见随仓库交付的 `docs/绿联NAS部署指南.md`）：
1. **图形化一键容器部署**：提供标准 `docker-compose.yml`，挂载 `/volume1/docker/timebook/data:/data`，用户只需在绿联桌面打开「`Docker` → 项目 → 创建」，粘贴配置并填入自己的访问口令即可一键启动。
2. **协议自适应登录 `Cookie`**：`COOKIE_SECURE` 默认设为 `auto`（根据 `HTTPS` 连接或反向代理/`Tailscale` 转发的 `X-Forwarded-Proto: https` 自动启用 `Secure` 属性；局域网初次通过 `http://<NAS局域网IP>:3210` 访问验收时自动兼容，不会出现因浏览器拦截 `Secure Cookie` 而无法登录的问题）。
3. **外网访问与 `PWA` 真 `HTTPS` 证书（零成本免域名方案）**：推荐在绿联 `Docker`（或同一 `docker-compose` 可选配置）中启用 **`Tailscale`** 并开启后台 `MagicDNS` 与 `HTTPS Certificates`（`tailscale serve` 将 `443` 映射至 `timebook:3210`）：
   - 无需购买公网域名、无需备案、无需暴露家庭公网端口；
   - 自动获得浏览器原生信任的 `https://<设备名>.<tailnet>.ts.net` 免费证书，手机浏览器打开可直接「添加到主屏幕」作为全屏 `PWA` 使用；
   - 在家连同一局域网时自动走内网点对点直连，在外自动走加密组网隧道，手机和电脑永远共用同一个网址。

## 4. 预算与验收标准（已确认 `C-06`）

- **产品运行时模型成本**：**`0 Token`、`0` 次外部模型请求**。
- **前端与容器性能目标**：5,000 条记录规模下统计与空档计算 `< 20ms`，容器常驻内存 `< 150MB`。
- **研发与独立 `QA` 预算**：最多 **3 轮**修复循环；单验收场景隔离子智能体盲测目标时长 `<= 8 分钟`（硬上限 `15 分钟`），`Token` 依宿主真实日志提取（无则记不可用，禁估算）。
- **六项必过验收场景**：`A1` 鉴权/健康检查/断网队列补传；`A2` 今日页多计时并行/空档补录/待办编辑与重复；`A3` 标签迁移与删除保待办/30 天回收站恢复；`A4` 日历拖拽与跨零点四周期双维度统计核对；`A5` 真实 `Notion` 结构 `CSV` 导入对账/导出/整批撤销；`A6` 手机端视图/`PWA` 构建与单进程生产托管备份验证。具体判据见 [v1.0.0 测试计划](timebook-v1.0.0-test-plan.md)。
