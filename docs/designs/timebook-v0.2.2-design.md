## 1. 业务合同

- **使用者与触发**：个人单用户在浏览器、`PWA` 及 `Windows` 桌面端（主窗口、置顶灵动胶囊及全局快捷键呼出框）中：
  1. 在「今日」页点击「开始专注」按钮发起新的专注；
  2. 在桌面端点击灵动胶囊「+ 新建专注」（含空闲态「+ 开始专注」或全局快捷键 `Ctrl+Alt+T`）呼出快捷选框；
  3. 在「标签」页对二级事项点击「停用」或「重新启用」。
- **输入与来源**：
  1. 「今日」页开始专注表单输入的专注内容（允许留空）与选中的时间标签（允许不选，记为「未分类」）；
  2. 灵动胶囊快捷选框内点击任意未完成待办简约小标签，或输入专注内容并按一级模块分类点选时间标签；
  3. 「标签」页停用 / 启用操作及桌面连家庭 `NAS` 服务端的实时同步响应。
- **输出与去向**：
  1. **今日页先确认再计时**：点击「开始专注」先弹出弹窗填写内容、点选按一级模块分组的标签，仅在按回车键或点「开始」时才创建专注记录并启动计时；点「取消」或 `Esc` 不产生任何记录；
  2. **灵动胶囊快捷双操作**：快捷选框上方展示简约待办小标签（默认全部未完成按截止时间排序，可切「仅今日」），单击即关联该待办直接开始计时并收起选框；下方提供内容输入与与主界面一致的一级模块分类时间标签排布，按回车或点「开始」起表；
  3. **停用状态稳定持久化与服务端版本识别**：无论单机模式还是桌面端连新版 `v0.2.2` `NAS` 服务端，停用标签即时隐藏且持续生效不反弹；若服务端仍为旧版（未支持或静默丢弃 `disabled_at`），客户端立即识别并弹出醒目中文横幅提示升级 `NAS` 容器镜像，绝不无声回滚。
- **完成判据**：
  - 全仓 `TypeScript` 类型检查、全仓 `Vitest` 单测与集成测试、`Rust` 原生单测、全栈构建（含 `PWA`）及 `Windows` 桌面安装包编译 100% 通过；
  - 四项独立隔离验收场景（`Q1`–`Q4`）全部满足合格判据，且关键界面视觉截图经独立核验符合 [视觉与动效设计规范](../设计规范.md)。
- **质量底线（不可妥协）**：
  1. **取消即零副作用**：在今日页「开始专注」弹窗或灵动胶囊快捷选框中点「取消」或按 `Esc` 关闭时，严禁创建或残留任何进行中或空专注记录；
  2. **输入法友好与防误触**：两个弹窗中处理 `Enter` 快捷键提交时必须拦截中文输入法选词组合态（`!e.isComposing && e.keyCode !== 229`），避免打字选词误提交；
  3. **全站启用过滤一致**：今日页「开始专注」弹窗与灵动胶囊快捷选框中的时间标签组均只显示启用中二级标签（`enabledTags`），已停用标签不得出现；
  4. **停用不静默回滚**：绝不允许因异步同步竞态或旧服务端忽略字段导致「停用后短暂消失又默默恢复原状且毫无提示」。
- **本版非目标（明确不做）**：
  - 不改变进行中计时卡片右上角「换标签 / 选标签」的极简点选交互；
  - 不对一级模块增加停用功能；
  - 不改变统计、日历、历史、待办截止排序既定算法。

## 2. 关键设计与交互细则

### 2.1 今日页「开始专注」弹窗升级（已确认 `C-22`）

1. **交互流程变更**：
   - 点击「今日」页顶部「开始专注」按钮时，**不再预先调用 `startTimer`**；改为打开「开始专注」表单弹窗（`StartFocusModal`，`data-testid="start-focus-modal"`）；
   - 进行中计时卡片右上角点击「换标签 / 选标签」继续复用原 `TagPickerModal`（已有计时点一下即换标签，体验不变）。
2. **弹窗内容与交互细节**：
   - **头部**：「开始专注」标题与温和说明（「填写专注内容并点选标签，按回车或点击「开始」后正式计时」），以及右上角关闭按钮 `✕`；**不显示**「计时已经开始」徽标；
   - **专注内容输入框**：`data-testid="start-focus-title-input"`，打开弹窗时自动聚焦（`autoFocus`），占位提示「这次准备专注做什么？（可选，按 Enter 直接开始）」，允许留空；
   - **时间标签选择区（复用共享 `ModuleTagGroups`）**：
     - 严格按一级模块（`lookup.activeModules`）分组，逐组展示模块色点 + 模块名，以及该模块下所有**启用中**二级事项标签（`lookup.enabledTags`，若某模块下无启用事项则跳过该模块）；
     - 标签胶囊遵循 [设计规范](../设计规范.md) 数据色浅底/深字/描边；点击某标签即选中（`2px` 墨色描边 `inset 0 0 0 2px #111827`），**再次点击已选中标签可取消选中**；右侧显示当前选中状态提示（如 `已选：工作 · 个人工作` 或 `当前：未分类`）；
   - **底部操作栏**：
     - 左侧辅助链接按钮：「不选标签（直接记为未分类）」——清除当前已选标签（或直接保持未选状态）；
     - 右侧主操作按钮组：「取消」（`data-testid="start-focus-cancel-btn"`）与主操作黄按钮「开始」（`data-testid="start-focus-submit-btn"`）；
   - **键盘行为**：
     - 弹窗打开时按 `Esc` 关闭弹窗，不做任何写入；
     - 在输入框或弹窗内（非取消/关闭/清除按钮聚焦且非待办按钮场景，且 `!e.isComposing && e.keyCode !== 229`）按 `Enter` 直接提交并调用 `startTimer({ tagId, title: title.trim() || null })`，随后关闭弹窗；防连点加提交锁。

### 2.2 灵动胶囊「新建专注」快捷选框升级（已确认 `C-23`）

1. **触发与窗口尺寸适配**：
   - 灵动胶囊悬停展开卡片中的「`+ 新建专注`」、空闲紧凑胶囊的「`+ 开始专注`」以及系统全局快捷键（默认 `Ctrl+Alt+T`）继续统一唤起 `launcher` 窗口（`LauncherPage.tsx`）；
   - `apps/desktop/src-tauri/tauri.conf.json` 中 `launcher` 窗口默认尺寸由 `460 × 268` 调整为 **`540 × 520`**（仍保持居中、透明无边框、置顶、不入任务栏），并在打开时自动居中和聚焦，确保双区域一屏舒展呈现而不溢出裁切。
   - **开窗数据刷新**：`LauncherPage` 在收到 `onLauncherOpened` 事件或窗口获得焦点时立即调用 `syncFromBridgeUpdate()`（或复用现有桥接刷新），保证每次呼出选框看到的待办完成态、新待办与标签启用状态都是最新状态。
2. **双操作布局规范**：
   - **头部栏**（支持 `data-tauri-drag-region` 拖拽移动）：左侧黄点品牌标 + 「新建专注」，右侧快捷键提示「点待办秒开 · Enter 开始 · Esc 取消」+ 关闭按钮 `✕`；
   - **操作区一（上方）：从未完成待办简约小标签直接开始**：
     - 标题行：左侧「点未完成待办直接开始」+ 数量徽标（`data-testid="launcher-todo-count"`）；右侧胶囊分段切换 **「全部未完成」 / 「仅今日」**（默认选中「全部未完成」）；
     - 数据源复用 `@timebook/core`：
       - 「全部未完成」：`getAllPendingTodos(todos, todoChecks, sessions, todayStr, nowMs()).filter((item) => !item.done)`（天然已按截止时间由近到远、无截止日期排最后最新创建在前的统一顺序）；
       - 「仅今日」：`getTodayTodos(todos, todoChecks, sessions, todayStr, nowMs()).items.filter((item) => !item.done)`；
     - **简约小标签样式**：不再展示完整待办卡片，每条待办渲染为紧凑单行小胶囊按钮（`data-testid="launcher-todo-${item.todo.id}"`，高约 `31px`、最大宽 `220px`、`border-radius: 999px`、带所属模块色点、单行省略号截断标题、右侧轻播放三角图标，`title` 属性保留完整待办名称方便鼠标悬停查看全称；悬停时亮起主操作黄 `#FFD43B`）；待办区域设置最大高度与纵向滚动（`maxHeight: 82px; overflowY: auto`），无待办时显示温和单行空状态提示；
     - **点击动作**：单击任意待办小标签，立即调用 `startTimer({ tagId: td.tag_id, title: td.title, todoId: td.id })` 并立即调用 `desktopBridge.windowAction('hideLauncher')` 归还焦点。
   - **分隔线**：`1px solid #EEF0F5` 浅灰水平分割。
   - **操作区二（下方）：填写专注内容 + 按一级标签分类点选时间标签**：
     - 标题行：左侧「或填写专注内容并选标签」，右侧实时回显当前已选状态（如 `已选：工作 · 个人工作` 或 `当前：未分类`）；
     - 专注内容输入框（`data-testid="launcher-title-input"`）：自动聚焦，占位提示「输入专注内容（可选，按 Enter 开始）」；
     - **时间标签排布**：直接复用与主界面 `StartFocusModal` 相同的共享组件 `ModuleTagGroups`（`compact` 紧凑尺寸）——**按一级模块分类展示所有启用中二级标签**（替代原先仅平铺 8 个最近常用标签的逻辑），隐藏已停用标签，支持点击选中 / 再点取消选中；容器设置适当最大高度并允许内部平滑滚动；
     - 底部操作栏：左侧「清空所选标签（记为未分类）」+ 右侧「取消」（`data-testid="launcher-cancel-btn"`）与黄色主按钮「开始」（`data-testid="launcher-start-btn"`）。

### 2.3 标签停用短暂消失后复原 Bug 修复与加固（已确认 `C-24`）

针对用户实机复现场景（桌面端连接家庭 `NAS` 服务器模式）与全链路同步流程，实施以下三层修复与防呆保护：

1. **服务端版本与能力声明（`apps/api`）**：
   - `GET /api/health` 与 `GET /api/status` 返回体补充版本号与能力标识：
     - `version: '0.2.2'`
     - `capabilities: ['tag_disabled_at']`
   - 保持 `apps/api/src/sync.ts` 中对 `disabled_at` 的精确写入与旧客户端缺省保护。
2. **客户端防静默回滚与能力核验（`apps/web/src/store/useAppStore.ts`）**：
   - **严格整型时间戳**：`setTagDisabled(id, disabled)` 统一写入 `disabled_at: disabled ? Math.trunc(get().nowMs()) : null`，杜绝因 `clockOffsetMs` 或系统时间出现非整数被后端 `Zod` `z.number().int()` 校验拒绝（返回 `400`）；
   - **服务端停用支持性检测与防静默回滚**：
     - 在 `tag.upsert`（尤其是涉及停用/启用操作）刷新同步后，若从服务端 `/api/sync` 拉取返回的同 ID 标签出现以下任一情况，立刻判定**当前连接的 `NAS` 服务端版本过旧（尚未支持标签停用字段）**：
       1. 服务端返回的该标签对象**完全不含 `disabled_at` 键**（`!Object.prototype.hasOwnProperty.call(remoteTag, 'disabled_at')`）；或
       2. 刚请求将标签停用（`expectedDisabled === true`），提交成功且无待提交队列后，服务端紧接着返回的该标签 `disabled_at` 却为 `null` 或缺失；
     - 一旦检测到上述情况，在写入本地状态的同时**立即弹出醒目中文横幅提示**（`errorBanner`）：
       `「停用标签未在家庭 NAS 服务端生效：当前连接的 NAS 容器镜像版本过旧，请先将 NAS 端的 Timebook 镜像更新到最新版（v0.2.2+）」`
       确保问题一目了然，绝不静默反弹让用户误以为操作失效。
   - **消除并发拉取覆盖未提交乐观态的竞态**：
     - 在 `pullSyncDelta()` 执行 `persistDeltaSync` / `persistFullSync` 前（以及 `useAppStore.setState(...)` 之前），先读取 `localDb.pendingMutations.count()`；若本地仍有未刷清的待提交变更，先完成推送或在写回内存中保留待提交的本地修改不被后台定时/聚焦轮询（`focus` / `30s` `setInterval`）的旧快照覆盖。
3. **理顺桌面端本地落盘与跨窗广播顺序（`apps/web/src/store/useAppStore.ts`）**：
   - 在 `enqueueMutation` 中：
     - 计时器类动作（`session.upsert` / `session.cancel_running`）继续保留毫秒级 `emitFastRunningBroadcast` 让灵动胶囊秒表零延迟起跳；
     - 非计时器变更或完整同步时，确保**先 `await Promise.all([...dbTasks, ...])` 落盘 IndexedDB 后，再触发跨窗口状态广播与本地 JSON 快照落盘**，防止辅窗在主窗尚未落库前抢读到旧数据并触发相互覆盖。

## 3. 风险与预算

- **旧数据与跨端兼容**：`v0.2.2` 数据库表结构与 `v0.2.1` 完全一致，支持从 `v0.1.0` / `v0.2.0` / `v0.2.1` 直接无感覆盖升级；桌面连旧服务端时给出清晰升级提醒，不破坏既有数据。
- **产品运行时模型消耗**：**`0 Token`**（纯本地与自托管确定性逻辑，零外部大模型请求）。
- **体积与研发预算**：
  - `Windows` NSIS 安装包体积目标 `<= 15 MB`（硬上限 `25 MB`）；
  - `dev` ↔ `qa` 研发与独立盲测返修循环最多 **`3 轮`**；
  - 单验收场景隔离子智能体盲测硬上限 `900 秒`。
