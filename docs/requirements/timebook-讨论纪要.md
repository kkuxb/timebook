## 4. `v0.2.0` 迭代讨论与确认记录

- **发起背景（2026-11-19）**：`v0.1.0` 实操验收并完成历史数据导入后，用户发起 `v0.2.0` 迭代需求讨论，涵盖四项核心议题：① 新增「历史」模块（全量历史专注记录查看、多维时间/一二级标签筛选、搜标签与标题、单条直接修改标签/标题/起止时间、新增与删除、多选批量改标签与批量改标题）；② 定位并修复灵动胶囊中专注计时延后开始的问题；③ 优化「今日」页时间横条从 0 点起导致超三分之一睡眠时段长期空白的问题（兼顾偶尔凌晨加班记录）；④ 下线「从 `Notion` 导入历史数据」功能。
- **源码只读核查结论（2026-11-19）**：
  1. **灵动胶囊计时延后开始的真实根因（三层叠加）**：
     - 跨窗通知被全量磁盘写入与重复备份阻塞：`useAppStore.ts` 中点击开始计时后，先将全量 3,700+ 条记录写入本地库，再调用 `persistDesktopDiskAndTray` 把全量快照发往 `Rust` 落盘，而 `lib.rs` 的 `desktop_save_snapshot` 每次均无条件执行 `run_local_backup` 重写整份每日备份文件并扫描目录轮转，接着重建系统托盘菜单，**排在所有文件读写和托盘操作最后**才发出跨窗口广播通知灵动胶囊；
     - 胶囊窗口收信后全量重读且秒表刻未即时对齐：`WidgetPage.tsx` 收到广播后再次全量读取本地几千条记录，且 `nowTick` 仅靠固定的 `1000ms` 定时器刷新，未在状态更新瞬间同步当前时间，导致新计时到达时画面多卡在 `00:00:00` 等待下一秒触发；
     - 隐藏主窗口节流影响托盘开表：主窗口隐藏到托盘时，通过托盘快捷开始会将事件发给后台隐藏的主窗口执行，受浏览器内核后台节流影响进一步拖慢响应。
  2. **`Notion` 导入下线边界**：前端 `SettingsDrawer.tsx` 导入卡片与批次撤销、`apps/api` 三个 `/api/import/*` 路由及 `tools/notion-import` 包均可整体下线（仅需将导出 `CSV` 复用的轻量 `toCsv` 工具函数迁入 `@timebook/core`）；数据库已有记录的 `source='import'` 与 `import_batch` 历史存量数据保持原样，零损保留。
