# 时间簿（Timebook）需求澄清与讨论纪要

## 1. 背景与来源资料

- 原始仓库资料：[开发方案 v1.1](../开发方案.md)、[设计规范](../设计规范.md)、交互原型（`prototype/Today.dc.html`、`Calendar.dc.html`、`Stats.dc.html`、`Tags.dc.html` 及 `docs/screenshots/`）。
- 真实 `Notion` 工作区只读核查（2026-11-19，工作区「个人时间可视化管理」）：
  1. **`时间标签` 表（共 18 行活跃记录）**：采用单表自关联结构（列名：`标签`、`颜色`、`一级标签`、`二级标签`）。`一级标签` 为空的行即模块（共 4 个：`工作`、`学习`、`游戏`、`锻炼`）；`一级标签` 非空的行即具体事项（共 14 个：工作下含 `淘教`、`个人工作`、`行者`、`各培训机构合作`、`淘宝天下`、`阿布`；游戏下含 `星穹铁道`、`原神`、`绝区零`、`单机游戏`、`异环`；学习下含 `钻研`、`Python`；锻炼下含 `健身`）。
  2. **`专注记录` 表（截至核查时共 3,712 条「已结束」+ 1 条「进行中」）**：
     - 列包含：`日历标题`（主键标题）、`状态`（`未开始` / `进行中` / `已取消` / `已结束`）、`标签`（关联）、`待办`（关联）、`开始`、`结束`。
     - **关键实证差异**：原方案 10.2 节写「将 `待办` 列映射为 `sessions.title`」，但真实数据中 `待办` 非空的仅有 **135 条**，而主键 **`日历标题` 非空的有 3,711 条**（例如标签为「各培训机构合作」而 `日历标题` 为「`FDE项目开发`」；标签为「单机游戏」而 `日历标题` 为「`影之刃零`」）。
     - 真实已结束记录中存在 **1 条未关联标签记录**（`no_tag = 1`），无结束时间缺失记录（`no_end = 0`）。
  3. **`待办` 表（共 46 条，当前全部为 `Done`）**：列包含 `事项`、`状态`、`执行日期`、`截止日期`、`完成时间`；**原表无「标签」列**。
- 真实家庭服务器（绿联 `NAS`）只读环境探针（2026-11-19，经用户授权通过 `SSH` 只读核查）：
  1. 设备型号与系统：绿联 `DXP4800 Plus`（`UGOS Pro`，`x86_64 Linux 6.18`），已内置 `Docker 29.x` 与 `Docker Compose v5.x`；存储卷 `/volume1/docker` 已就绪且剩余空间充足（`> 5TB`）。
  2. 网络现状：具备局域网 `IPv4` 与运营商动态公网 `IPv6`，当前未安装第三方内网穿透或反向代理证书组件，普通 `SSH` 登录账号默认未加入 `docker` 用户组（可通过绿联图形界面「`Docker` → 项目」直接导入 `docker-compose.yml` 启动，或使用管理员权限执行）。
